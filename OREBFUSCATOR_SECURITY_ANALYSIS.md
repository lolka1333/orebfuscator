# Анализ безопасности Orebfuscator для Minecraft 1.21.x

## Обзор архитектуры

Orebfuscator - это серверный плагин, который модифицирует пакеты чанков перед отправкой клиенту. Основная цель - скрыть руды и другие ценные блоки от X-Ray читов.

### Основные механизмы защиты:

1. **Obfuscation (Обфускация)**: Замена скрытых блоков на случайные блоки
2. **Proximity Hiding (Скрытие по близости)**: Раскрытие блоков только при приближении игрока
3. **Block Entity Hiding**: Скрытие сундуков, печей и других блок-энтити
4. **Frustum Culling**: Оптимизация на основе поля зрения игрока
5. **Ray Cast Check**: Проверка линии видимости до блока

## Слабые стороны и векторы обхода

### 1. Обнаружение через физику и механику блоков

#### 1.1 Анализ освещения (Lighting Analysis)
**Уязвимость**: Сервер отправляет настоящие данные об освещении
- Руды не излучают свет, но занимают пространство
- Пещеры и лава создают характерные паттерны освещения
- Клиент получает реальные уровни освещения (sky light, block light)

**Метод обхода**:
```java
// Анализ данных освещения из ChunkSection
// Orebfuscator заменяет blockState, но НЕ данные освещения
int lightLevel = chunkSection.getLightLevel(x, y, z);
// Несоответствие между замененным блоком и освещением может выдать реальный блок
```

**Код в Orebfuscator** (`ObfuscationProcessor.java:107-108`):
```java
chunkSection.setBlockState(index, blockState);
// Освещение НЕ обновляется! Это потенциальная утечка информации
```

#### 1.2 Анализ окклюзии (Occlusion Analysis)
**Уязвимость**: Логика обфускации основана на проверке соседних блоков
- Блок обфусцируется только если все 6 соседей - непрозрачные (`isOccluding`)
- Это создаёт характерные паттерны на границах пещер и руд

**Код в Orebfuscator** (`ObfuscationProcessor.java:140-147`):
```java
private boolean shouldObfuscate(ObfuscationTask task, Chunk chunk, int x, int y, int z) {
  return isAdjacentBlockOccluding(task, chunk, x, y + 1, z)
      && isAdjacentBlockOccluding(task, chunk, x, y - 1, z)
      && isAdjacentBlockOccluding(task, chunk, x + 1, y, z)
      && isAdjacentBlockOccluding(task, chunk, x - 1, y, z)
      && isAdjacentBlockOccluding(task, chunk, x, y, z + 1)
      && isAdjacentBlockOccluding(task, chunk, x, y, z - 1);
}
```

**Метод обхода**:
- Блоки на границе пещеры/воздуха НЕ обфусцируются
- Можно строить карту "точно не руда" vs "может быть руда"
- Алгоритм кластеризации найдёт пещеры и жилы руд

#### 1.3 Анализ биомов и генерации
**Уязвимость**: Клиент знает биом и может предсказать расположение руд
- Deepslate diamonds на Y=-59 до Y=-64
- Изумруды только в горных биомах
- Древний мусор на определённых Y-уровнях

### 2. Временные атаки (Timing Attacks)

#### 2.1 Анализ задержки обновления блоков
**Уязвимость**: Proximity Hider раскрывает блоки при приближении с задержкой

**Код в Orebfuscator** (`ProximityWorker.java:79-154`):
- Proximity worker работает периодически (через ProximityDirectorThread)
- Есть заметная задержка между приближением и раскрытием блока
- Блоки "мигают" при загрузке

**Метод обхода**:
```java
// Записывать все изменения блоков при движении
Map<BlockPos, List<BlockUpdate>> blockHistory = new HashMap<>();

// При получении пакета обновления блока:
if (wasStoneNowDiamond(oldBlock, newBlock)) {
  // Это был proximity-скрытый блок -> настоящая руда
  markAsRealOre(blockPos);
}
```

#### 2.2 Анализ событий деобфускации
**Уязвимость**: При ломании блоков соседние блоки деобфусцируются

**Код в Orebfuscator** (`DeobfuscationWorker.java:82-102`):
```java
public void processPosition(BlockPos position, int depth) {
  // Рекурсивно обновляет блоки в радиусе updateRadius
  if (depth-- > 0) {
    processPosition(position.add(1, 0, 0), depth);
    processPosition(position.add(-1, 0, 0), depth);
    // ... все 6 направлений
  }
}
```

**Метод обхода**:
- Ломать камень и наблюдать за изменениями соседних блоков
- Если блок изменился с камня на алмаз - это был обфусцированный алмаз
- Особенно эффективно с `updateRadius > 1` (по умолчанию 2)

### 3. Статистический анализ

#### 3.1 Анализ частоты появления блоков
**Уязвимость**: Обфусцированные блоки имеют другое распределение

**Код в Orebfuscator** (`AbstractWorldConfig.java`):
```java
// randomBlocks с весами:
// stone: 80%
// diamond_ore: 5%
// gold_ore: 5%
// ...
```

**Метод обхода**:
- В реальном мире: 99.9% камня, 0.01% алмазов
- В обфусцированных чанках: 80% камня, 5% алмазов
- Если видишь слишком много алмазов/золота -> они поддельные
- Если видишь необычно мало камня -> чанк обфусцирован

#### 3.2 Layer Obfuscation
**Уязвимость**: При включенном `layerObfuscation` все блоки на одном Y-уровне заменяются одинаково

**Код в Orebfuscator** (`ObfuscationProcessor.java:82-90`):
```java
if (obfuscationConfig.layerObfuscation()) {
  if (layerY != y) {
    layerY = y;
    layerYBlockState = bundle.nextRandomObfuscationBlock(y);
  }
  blockState = layerYBlockState;
}
```

**Метод обхода**:
- Все обфусцированные блоки на Y=-59 будут, например, камнем
- Все на Y=-60 будут золотом
- Создаёт характерные "слои" - очень легко детектировать

### 4. Анализ сетевых пакетов

#### 4.1 Размер пакетов и компрессия
**Уязвимость**: Обфусцированные чанки могут иметь другой размер после сжатия
- Случайные блоки хуже сжимаются
- Пещеры с рудами имеют определённую структуру

#### 4.2 Block Entity пакеты
**Уязвимость**: Orebfuscator скрывает NBT данные блок-энтити, но клиент может детектировать удаление

**Код в Orebfuscator** (`ObfuscationProcessor.java:109-111`):
```java
if (BlockFlags.isBlockEntityBitSet(obfuscateBits)) {
  blockEntities.add(new BlockPos(x, y, z));
}
// Позже эти blockEntities удаляются из пакета
```

**Метод обхода**:
- Если блок выглядит как сундук, но нет NBT -> подделка
- Если блок выглядит как камень в месте, где должен быть сундук -> скрытый сундук

### 6. Математические атаки

#### 6.1 Обратная инженерия PRNG
**Уязвимость**: Если random seed предсказуем, можно различить реальные и поддельные блоки

**Потенциальный код**:

```java
// Если Orebfuscator использует предсказуемый Random:
Random rng = new Random(chunkX ^ chunkZ ^ world.getSeed());

```

#### 6.2 Паттерн-матчинг через машинное обучение
**Метод обхода**:
- Собрать датасет обфусцированных vs реальных чанков
- Обучить нейросеть распознавать паттерны
- Признаки: распределение блоков, освещение, форма пещер

## Рекомендации по защите

### Для администраторов серверов:

1. **Включить все механизмы защиты**:
   ```yaml
   obfuscation:
     enabled: true
     layerObfuscation: false  # ОТКЛЮЧИТЬ - создаёт паттерны
   proximity:
     enabled: true
     distance: 16  # Меньше = безопаснее, но больше нагрузка
     frustumCulling.enabled: true
     rayCastCheck.enabled: true
   ```

2. **Настроить правильные randomBlocks**:
   - Использовать только обычные блоки (stone, andesite, diorite)
   - НЕ включать руды в список замены (это создаёт шум)

3. **Уменьшить updateRadius**:
   - По умолчанию 2 - позволяет видеть руды через деобфускацию
   - Установить в 1 для большей безопасности

4. **Мониторинг**:
   - Логировать игроков, которые находят слишком много руд
   - Использовать античит для детекта X-ray поведения

### Для разработчиков Orebfuscator:

1. **Обфускация освещения**: Добавить ложные источники света
2. **Динамическая обфускация**: Изменять паттерны замены для каждого игрока
3. **Обфускация биомов**: Отправлять ложную информацию о биомах
4. **Анти-статистика**: Подстраивать распределение блоков под реальное
5. **Задержка деобфускации**: Добавить случайную задержку перед раскрытием блоков

## Вывод

Orebfuscator - это эффективная защита от простых X-ray читов, но имеет фундаментальные ограничения:

**Сильные стороны**:
- Защищает от базовых texture pack X-ray
- Защищает от простых модов с прозрачностью
- Минимальная нагрузка на клиент

**Слабые стороны**:
- Уязвим к анализу освещения и физики
- Деобфускация при ломании блоков выдаёт информацию
- Статистические аномалии в распределении блоков
- Proximity Hider создаёт временные паттерны
- Не защищает от продвинутых читов с анализом пакетов

**Обход возможен**, но требует:
- Глубоких знаний протокола Minecraft
- Разработки кастомного клиентского мода
- Анализа сетевых пакетов или механики игры
- Может быть детектирован хорошими античитами

Для максимальной безопасности рекомендуется использовать Orebfuscator в сочетании с:
- Античит-плагинами (Matrix, Vulcan, Grim)
- Мониторингом статистики добычи
- Ограничением permissions и spectator mode
